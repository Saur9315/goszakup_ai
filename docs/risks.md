# Риски и ограничения

Для каждого пункта указано, как он проявляется в данных, что уже сделано и что видит пользователь в ответе.

## Методические ограничения

- **Неоднородность кодов ЕНС ТРУ.** Под одним кодом встречаются товары разного класса: «Микроскоп» за 250 млн ₸ и за 2 тыс. ₸. Что сделано:
  - описания из пунктов плана переводятся в эмбеддинги и группируются в подклассы; если под кодом товары разного класса, сравнение идёт внутри подкласса;
  - вердикт по цене опирается на медиану и robust z-score, неоднородные группы помечаются;
  - аномалии делятся на «по критерию ТЗ» и «подтверждённые».

  Что остаётся. Модель различает классы внутри кода не резко, а у части позиций описания нет (выборка по порталу без связи с планом) — для них сравнение идёт по всему коду. Порог кластеризации подобран по данным и может требовать пересмотра при росте выборки.
- **Модель эмбеддингов.** Используется int8-версия модели, оптимизированная под процессоры с AVX512-VNNI. На старых CPU она работает, но точность целочисленных операций может быть ниже. Модель зашита в образ с проверкой sha256; при её смене все описания пересчитываются автоматически (около 8 минут).
- **Упаковки.** Цена за упаковку сравнивается только с ценами за упаковку, но размер упаковки неизвестен. Уверенность для таких единиц снижена.
- **Услуги и работы.** Цена за «одну услугу» несопоставима; такие позиции исключены из Fair Price и аномалий.
- **Короткая история.** Три года данных позволяют сравнить объёмы только с 1–2 предыдущими годами. Коды ЕНС ТРУ меняются между годами, и позиции без истории не попадают в сравнение.
- **Инфляция.** Используется общий ИПЦ. Индексы по группам (продовольственные, непродовольственные товары, услуги) загружены, но пока не применяются. Для договоров текущего месяца ИПЦ ещё не опубликован, берётся последний известный (8,9% позиций).
- **Сезонность** оценена по всем товарам сразу. Октябрьская надбавка (+8,2%) может отражать и поведение заказчиков в конце бюджетного года, а не только рынок.
- **Региональный коэффициент** — средний по всем товарам; для отдельных товарных групп региональная разница может быть другой.
- **Плановые цены.** Эмпирически сопоставимы с ценами без НДС, но в нормативных документах этот вопрос не проверялся.
- **Переплата** в аномалиях цен — оценка относительно средневзвешенной, а не установленный факт нарушения.

## Риски LLM

| Риск | Что сделано |
|---|---|
| Выдуманные цифры | LLM не считает; числа берутся из инструментов; каждое число в тексте сверяется с фактами, при расхождении — повтор; итог проверки виден в ответе («Проверка цифр: N из M») |
| Неверный тип вопроса | на эталонном наборе 100% для всех трёх моделей; при ошибке инструмент всё равно возвращает корректные данные, но не о том |
| Неверная организация | список 27 организаций передаётся в подсказку, БИН проверяется по базе; на наборе 100% |
| Недоступность модели | резервный провайдер; при сбое на этапе ответа — шаблонный вывод из фактов с пометкой |
| Задержка и лимиты локальной модели | Qwen3-8B с лимитом 15 запросов в минуту отвечает за 24 с (p50); для интерактивной работы нужна модель без таких лимитов или своя на GPU |
| Утечка данных во внешнюю LLM | данные публичные; для закрытого контура — своя модель через `OPENAI_BASE_URL` (vLLM), проверено на Qwen3-8B |
| Prompt injection | вопрос не попадает в SQL; инструменты только читают данные; текст модели не исполняется |
| Изменение поведения модели при обновлении | версия подсказок хранится в каждом ответе; эталонный набор прогоняется одной командой |

## Безопасность

- **Секреты.**
  - Токен OWS, ключи LLM и пароли хранятся в `.env` (исключён из git) или в Secret Kubernetes.
  - Токен отправляется только на хост OWS и не попадает в логи.
  - История git проверена на отсутствие ключей.
- **Права.**
  - API работает под ролью `goszakup_api`: чтение `core`, `mart`, `meta`; запись только в журнал ответов и память диалогов; доступа к `raw` нет.
  - Права проверены: попытка изменить данные отклоняется.
- **Изоляция.** Токен OWS есть только у загрузки, ключи LLM — только у API. В Kubernetes доступ к Postgres ограничен NetworkPolicy.
- **Открытые вопросы.**
  - Вход в API включается переменной `AUTH_SECRET`:
    - пароли хранятся как scrypt-хеши, токены подписаны HMAC и действуют 12 часов;
    - диалоги привязаны к пользователю, чужой диалог отдаёт 404;
    - отключение пользователя сразу аннулирует его токены.

    Ограничения частоты запросов и защиты от перебора паролей нет, TLS не настроен — перед публикацией за пределы внутренней сети нужен обратный прокси или шлюз. Для промышленной эксплуатации вход лучше перевести на корпоративный SSO (OIDC, например Keycloak).
  - Веб-интерфейс на Streamlit — демонстрационный клиент, а не портал: одна реплика, без ролей и аудита действий.
  - Журнал ответов хранит вопросы пользователей; для персональных данных понадобится политика хранения.

## Эксплуатация

- **Объём.**
  - Выборка цен по порталу ограничена кодами, покрывающими 95% затрат, и 200 договорами на код и год.
  - Для остальных кодов Fair Price опирается на договоры 27 организаций и может выдать «недостаточно данных».
- **Время загрузки.** Первичная загрузка выборки по порталу занимает около часа; дальше она обновляется инкрементально раз в неделю.
- **Хранение.**
  - Слой `raw` хранит полные ответы API, около 0,7 млн объектов, и растёт со временем.
  - Нужна политика очистки старых версий и резервное копирование (в Kubernetes Postgres развёрнут как StatefulSet, для промышленной эксплуатации лучше управляемый кластер).
- **Масштабирование.**
  - API без состояния: память диалогов в Postgres, можно запускать несколько реплик.
  - Узкое место — LLM: при росте нагрузки нужна своя модель на GPU или квоты провайдера.
- **Не проверено вживую.** Профиль локальной модели vLLM проверен только синтаксически: на тестовой машине Docker не видит GPU. Манифесты Kubernetes проверены kubeconform, но не разворачивались в кластере.
