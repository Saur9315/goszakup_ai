# Аналитика и метрики

Все показатели считаются в SQL-витринах (`backend/src/goszakup_ai/marts/definitions.py`) и Python-модулях (`backend/src/goszakup_ai/analytics`). LLM получает готовые результаты.

## Нормализация данных

**Цена.** Для сравнения берётся цена за единицу без НДС из позиции актуальной версии договора (`item_price`), в тенге (договоры в валюте пересчитываются по курсу договора), за нормализованную единицу:

```math
p = \frac{\text{цена} \cdot \text{курс}}{k_{\text{ед}}}, \qquad q = \text{количество} \cdot k_{\text{ед}}
```

НДС исключается, потому что поставщики бывают плательщиками и неплательщиками НДС. Плановые цены и суммы лотов сопоставимы с ценами без НДС: проверено на данных, плановая цена совпадает с ценой договора без НДС в 22,4% позиций и с ценой с НДС только в 0,6%.

**Единицы измерения.** Таблица `core.ref_unit_norm` (44 единицы, засеяна миграцией) задаёт каноническую единицу и коэффициент:

| Класс | Примеры | Сравнение |
|---|---|---|
| масса | т → кг (×1000), г → кг (×0,001) | по кг |
| объём | мл → л, м³ → л (×1000), декалитр → л | по л |
| длина, площадь | погонный метр → м, м² общей площади → м² | по м, м² |
| количество | сто штук → шт (×100), единица → шт | по шт |
| упаковки | упаковка, пачка, флакон, набор, комплект, ампула | только внутри своей единицы; уверенность ниже |
| услуги, работы | одна услуга, работа | цена за единицу несопоставима, исключаются |

**Названия.** Функция `clean_name` убирает номера лотов, кавычки и служебные префиксы («Поставка», «Приобретение», «Закуп»), заменяет латинские буквы внутри кириллических слов на кириллические (включая казахскую «і»), приводит к нижнему регистру. На лотах это сократило число уникальных названий с 5 704 до 5 613.

**Место поставки.** Берётся КАТО пункта плана с наибольшим количеством, при его отсутствии — первый КАТО из адреса заказчика (в 53% позиций; API отдаёт места поставки примерно для трети пунктов плана).
- **Регион** — первые 2 цифры КАТО + `0000000`.
- **Город** — для Астаны, Алматы и Шымкента совпадает с регионом, для остальных — уровень городской администрации или района: первые 4 цифры + `00000`.

**Актуальная версия договора** — последняя неудалённая в цепочке допсоглашений; договоры со статусом «Не заключен» исключаются.

## Fair Price

ТЗ требует учесть три фактора: сравнительный подход по кодам ЕНС ТРУ, региональный коэффициент и временной фактор (инфляция и сезонность).

**Оцениваемая цена $`p_t`$.** Цена позиции договора по лоту. Если договор не заключён, берётся объявленная цена лота: сумма, делённая на количество.

**Аналоги** $`j`$ — позиции актуальных договоров:
- тот же код ЕНС ТРУ и та же нормализованная единица;
- единица сопоставима (не услуга);
- надёжная связь с пунктом плана (шаги 1–4 восстановления, см. [data-model.md](data-model.md));
- **другой заказчик** («аналогичные контракты других ведомств») и другая цепочка договора;
- $`p_j > 0`$, $`q_j > 0`$.

Источник аналогов — договоры 27 организаций и выборка договоров всех заказчиков РК по тем же кодам.

**Уровень выборки.** Город поставки → регион → вся РК; берётся первый уровень, где $`N \ge 5`$.

**Поправки.** Цена каждого аналога приводится к условиям оцениваемой закупки:

```math
\tilde p_j = p_j \cdot \frac{I(m_t)}{I(m_j)} \cdot \frac{S(\mu_t)}{S(\mu_j)} \cdot \frac{K(r_t)}{K(r_j)}
```

- **Инфляция** $`I(m)`$ — накопленный индекс потребительских цен на месяц подписания по официальному ряду Бюро национальной статистики (январь 2024 — сентябрь 2026). Для месяцев, по которым ИПЦ ещё не опубликован, берётся последний опубликованный.
- **Сезонность** $`S(\mu)`$ — коэффициент месяца, оценённый по данным. Для каждой группы «код × единица × год» не меньше чем из 6 наблюдений считается отношение очищенной от инфляции цены к медиане группы; берётся медиана логарифмов отношений по месяцу со сжатием к 1:

  ```math
  S(\mu) = \exp\Big(\tfrac{n_\mu}{n_\mu + 500} \cdot \operatorname{median}\ln\tfrac{p^{real}}{\operatorname{med}_{\text{группы}}}\Big)
  ```

  Результат: почти все месяцы нейтральны (1,000), сентябрь — 0,966, **октябрь — 1,076**. Октябрьская надбавка похожа на эффект «освоения бюджета» в конце года.
- **Регион** $`K(r)`$ — региональный коэффициент цен; применяется только на уровне «вся РК». Для кодов, встречающихся хотя бы в двух регионах, считается отношение медианы цены в регионе (не меньше 3 наблюдений) к медиане по стране; берётся медиана логарифмов по кодам со сжатием к 1 при малом числе кодов:

  ```math
  K(r) = \exp\Big(\tfrac{n_r}{n_r + 20} \cdot \operatorname{median}_{c}\ln\tfrac{\operatorname{med}_{c,r}}{\operatorname{med}_c}\Big)
  ```

| Регион | $`K`$ | Регион | $`K`$ |
|---|---|---|---|
| область Ұлытау | 1,105 | Акмолинская | 0,988 |
| область Жетісу | 1,062 | Шымкент | 0,969 |
| Астана | 1,035 | Атырауская | 0,967 |
| Алматы | 1,000 | Западно-Казахстанская | 0,955 |
| Карагандинская | 0,990 | Туркестанская | 0,924 |

**Оценка.** Fair Price — взвешенная медиана скорректированных цен аналогов с весом $`w_j = \sqrt{q_j}`$; коридор — взвешенные квантили P25–P75:

```math
FP = \operatorname{wmedian}(\tilde p_j;\ \sqrt{q_j}), \qquad \delta = \frac{p_t}{FP} - 1
```

Почему не средневзвешенная: она чувствительна к выбросам и к одной крупной закупке. Например, для лота «Автомобиль» средневзвешенная по количеству — 13,7 млн ₸ (её тянут вниз массовые закупки недорогих машин), а взвешенная медиана — 19,8 млн ₸. Вес $`\sqrt{q}`$ даёт крупным закупкам больший вклад, но не позволяет одной из них определить результат. Средневзвешенная по количеству (как в формулировке ТЗ) показывается рядом.

**Robust z-score** цены относительно аналогов: $`z = \dfrac{\ln p_t - \operatorname{median}\ln\tilde p}{1{,}4826 \cdot \operatorname{MAD}(\ln\tilde p)}`$.

**Вердикт:**

| $`\delta`$ | Вердикт |
|---|---|
| > +30% | цена завышена |
| +15%…+30% | выше рынка |
| −30%…+15% | в пределах рынка |
| < −30% | аномально низкая (возможна ошибка единиц или демпинг) |
| $`N < 5`$ на уровне РК | недостаточно данных |

**Уверенность** — произведение множителей:

```math
c = \underbrace{(1 - e^{-N/8})}_{\text{объём}} \cdot \underbrace{\frac{1}{1 + (P75 - P25)/FP}}_{\text{разброс}} \cdot \underbrace{f_{\text{ур}}}_{1;\ 0{,}9;\ 0{,}8} \cdot \underbrace{f_{\text{связи}}}_{1;\ 0{,}9;\ 0{,}6} \cdot \underbrace{f_{\text{упак}}}_{1;\ 0{,}8}
```

- $`f_{\text{ур}}`$: город, регион, РК;
- $`f_{\text{связи}}`$: прямая связь с пунктом плана, через заказчика и код, единица восстановлена по коду;
- $`f_{\text{упак}}`$: штучная единица или упаковка.

Метка: высокая при $`c \ge 0{,}6`$, средняя при $`c \ge 0{,}35`$, иначе низкая.

Результат содержит до 10 аналогов (сначала из того же города, затем самые свежие) с исходной и скорректированной ценой и ссылками на договоры, а также список ограничений: малая выборка, уровень РК, восстановленная единица, упаковка, большой разброс, оценка объявленной цены лота.

## Аномалии цен

Вопрос ТЗ: «Найди закупки с отклонением цены > 30% от средневзвешенной по данному ЕНСТРУ».

1. Цены переводятся в сопоставимые по ИПЦ: $`p^{real} = p \cdot 100 / I(m)`$.
2. Группа — код ЕНС ТРУ × нормализованная единица, все заказчики РК, 2024–2026.
3. Для позиции $`i`$ одной из 27 организаций — средневзвешенная по количеству **без самой позиции**:
   ```math
   \bar p_{-i} = \frac{\sum_j p_j q_j - p_i q_i}{\sum_j q_j - q_i}, \qquad \delta_i = \frac{p_i}{\bar p_{-i}} - 1
   ```
4. **Критерий ТЗ:** $`\delta_i > 30\%`$ при не меньше чем 5 аналогах.
5. **Подтверждённая аномалия:** дополнительно $`|z_i| > 2`$ по медиане и MAD логарифмов цен группы. Средневзвешенная чувствительна к неоднородности: под одним кодом бывают товары разного класса (например, «Массив дисковый» за 71,5 млн ₸ рядом с массовыми за 240 тыс. ₸). Робастная проверка отсеивает такие случаи.
6. **Неоднородная группа** — MAD логарифма цены больше 0,7; отмечается в ответе.
7. **Оценка переплаты:** $`(p_i - \bar p_{-i}) \cdot q_i`$.

За 2025 год: проверено 18 780 позиций, по критерию ТЗ отмечено 6 992, подтверждено 1 373, оценка переплаты по подтверждённым — 2,35 млрд ₸.

## Аномалии объёмов

Вопрос ТЗ: «Выяви нетипичное завышение количества ТРУ по сравнению с предыдущими годами».

1. **Количество** по паре «заказчик × код ЕНС ТРУ × единица × год» берётся из годового плана (неудалённые пункты, кроме статуса «Изменен»). Если плана нет — из договоров. План 2026 года уже полный, поэтому неполнота текущего года сравнению не мешает.
2. **База** — среднее количество за предыдущие годы; рост $`R = q_y / \bar q_{\text{прошлые}}`$.
3. **Сравнение с коллегами:** медиана роста по тому же коду у других заказчиков выборки; превышение $`E = R / \operatorname{median}(R_{коллег})`$ при не меньше чем 4 коллегах.
4. **Формальный критерий:** $`R \ge 1{,}5`$ (настраивается). Услуги и работы исключаются: количество «услуг» не отражает объём.
5. **Подтверждённый рост** — Isolation Forest (scikit-learn, 200 деревьев, `random_state=42`). Модель обучается на всех парах «заказчик × код × год» по признакам $`\ln R`$, $`\ln E`$, $`\ln(1 + \text{сумма})`$ и относит к выбросам 5% самых нетипичных сочетаний. Рост подтверждён, если он выше порога и модель считает его выбросом.
6. **Сортировка:** сначала подтверждённые, внутри — по сумме прироста $`(q_y - \bar q)\cdot \text{сумма}/q_y`$.

Зачем модель: правилу $`R \ge 1{,}5`$ удовлетворяет около 28% всех пар, и в части из них рост общий для всех заказчиков (изменились нормы или рынок). Пороги по каждому признаку отдельно не различают «×1,6 на 200 тыс. ₸, коллеги выросли так же» и «×8 на 300 млн ₸, коллеги не росли». Isolation Forest оценивает сочетание признаков без ручных порогов: нетипичная точка отделяется от остальных за меньшее число случайных разбиений. Рост больше чем в 100 раз модель тоже отмечает. Обычно это разные единицы измерения в разные годы или ошибка в плане, и ответ об этом предупреждает.

Почему не LOF: внутри группы цена — одно число, и для одномерных данных robust z по MAD — стандартный и объяснимый выбор. Многомерная задача у нас одна, объёмы, и для неё выбран Isolation Forest: он не требует подбора числа соседей и не зависит от масштаба признаков.

Пример: Дирекция государственных резиденций планирует на 2026 год 421 тыс. л дизельного топлива против 161 тыс. в среднем за прошлые годы (×2,6), у других заказчиков объём не вырос (×0,93), сумма прироста — 81,9 млн ₸.

## Эффективность закупок

Витрина `procurement_efficiency`, по заказчику и году:

| Показатель | Определение |
|---|---|
| Экономия | $`1 - \sum(\text{цена договора} \cdot q) / \sum(\text{плановая цена} \cdot q)`$ по позициям с прямой связью с пунктом плана |
| Доля из одного источника | доля суммы договоров со способом «Из одного источника…» |
| Доля несостоявшихся лотов | лоты со статусом «Закупка не состоялась» |
| Доля отменённых лотов | «Отказ от лота», «Отменен» |
| HHI | сумма квадратов долей поставщиков в сумме договоров заказчика за год |
| Срок | средние дни от публикации объявления до подписания договора |

## Оценка точности агента

Требование ТЗ: точность извлечения фактов (цифр, дат, БИН) не меньше 85%.

**Набор** — 33 сценария, 36 вопросов, 99 проверяемых фактов (`backend/src/goszakup_ai/evals`):
- поиск;
- эффективность;
- сравнение;
- аномалии цен и объёмов;
- Fair Price;
- вопросы на казахском языке;
- диалоги с уточнениями;
- вопросы не по теме.

Организации названы так, как сказал бы человек («Больница МЦ УДП», «Национальный госпиталь»), в том числе с похожими названиями («ЛОК Ок-Жетпес» и «Ок-Жетпес Алматы»).

**Ожидаемые значения** считаются прямым SQL по витринам в момент прогона, поэтому набор не устаревает после синхронизации.

**Сопоставление.** Число в ответе распознаётся с единицами (млн, млрд, %) и считается совпавшим в пределах точности записи (например, «11,88 млрд ₸» совпадает с 11 882 млн ±5 млн). БИН, номера лотов и даты сравниваются по точному вхождению.

**Метрики:**
- точность фактов во всём ответе;
- точность фактов в тексте, написанном LLM;
- точность определения типа вопроса;
- точность извлечения БИН, номеров лотов и периода;
- доля подтверждённых чисел в тексте LLM;
- задержка;
- токены.

| **Точность фактов в ответе** | **100%** | **100%** | **99,0%** |
| Точность фактов в тексте LLM | 97,0% | 89,9% | 89,9% |
| Тип вопроса | 100% | 100% | 97,0% |
